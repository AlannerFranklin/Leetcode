# 146. LRU 缓存 (LRU Cache)

## 题目描述
请你设计并实现一个满足 **LRU (最近最少使用) 缓存** 约束的数据结构。
实现 `LRUCache` 类：
*   `LRUCache(int capacity)` 以正整数作为容量 `capacity` 初始化 LRU 缓存。
*   `int get(int key)` 如果关键字 `key` 存在于缓存中，则返回关键字的值，否则返回 `-1`。
*   `void put(int key, int value)` 如果关键字 `key` 已经存在，则变更其数据值 `value` ；如果不存在，则向缓存中插入该组 `key-value` 。如果插入操作导致关键字数量超过 `capacity` ，则应该 **逐出** 最久未使用的关键字。

**进阶要求**：`get` 和 `put` 必须以 **O(1)** 的平均时间复杂度运行。

## 解题思路

### 核心思想：哈希表 + 双向链表
为了同时满足：
1.  **查找快 (O(1))** -> 必须用哈希表 (`unordered_map`)。
2.  **插入/删除快 (O(1))** -> 必须用链表，而且是双向链表 (`list`)。
3.  **有序 (最近使用 vs 最久未使用)** -> 链表本身就有顺序。

### 数据结构设计
*   **双向链表 (`std::list<Node>`)**：
    *   **头部 (begin)**：存放**最近使用**的数据（热数据）。每次访问或插入，都把节点移到这里。
    *   **尾部 (back)**：存放**最久未使用**的数据（冷数据）。当缓存满时，直接淘汰这里的数据。
    *   **节点内容**：必须同时存 `key` 和 `value`。存 `key` 是为了淘汰节点时，能反向去哈希表里删除记录。

*   **哈希表 (`std::unordered_map<int, iterator>`)**：
    *   **Key**：题目给的 key。
    *   **Value**：指向链表节点的**迭代器**。这样我们就能通过 key 直接定位到链表中的节点，从而在 O(1) 时间内把它移到头部。

### 关键操作逻辑

#### 1. `get(key)`
*   **不存在**：返回 -1。
*   **存在**：
    1.  通过哈希表找到链表节点迭代器。
    2.  **关键**：使用 `splice` 将该节点移动到链表头部（标记为最近使用）。
    3.  返回节点的值。

#### 2. `put(key, value)`
*   **已存在**：
    1.  通过哈希表找到节点。
    2.  更新 `value`。
    3.  **关键**：移动到链表头部。
*   **不存在**：
    1.  **检查容量**：如果满了，删除链表尾部节点（同时删哈希表记录）。
    2.  **插入**：在链表头部插入新节点 `{key, value}`。
    3.  **记录**：在哈希表中记录 `key -> cacheList.begin()`。

### 复杂度
*   **时间复杂度**：`get` 和 `put` 均为 O(1)。
*   **空间复杂度**：O(capacity)。需要存储 capacity 个节点。
