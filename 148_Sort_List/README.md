# LeetCode 148. Sort List

## 题目描述

给你链表的头结点 `head` ，请将其按 **升序** 排列并返回 排序后的链表 。
要求时间复杂度为 `O(n log n)`，空间复杂度为 `O(1)` (不考虑递归栈空间)。

## 为什么这道题很重要？

这道题就是你 **Lemon Micro 笔试题 T1 (Linked List Sort)** 的核心原型。

*   **笔试题限制**：双向链表、In-place（原地）、禁止 `new` 节点。
*   **本题**：单向链表、`O(n log n)`。

虽然笔试题是双向链表且有更严格的工程限制，但**归并排序 (Merge Sort)** 的核心思想是一模一样的。掌握了这道题，你就能理解为什么归并排序是链表排序的最佳选择。

## 解题思路：归并排序 (Merge Sort)

对于数组排序，我们通常喜欢用快速排序 (Quick Sort)。但对于链表，**归并排序**是更好的选择，原因如下：

1.  **随机访问困难**：快排需要随机访问元素（下标操作），链表做不到。
2.  **归并的天然优势**：归并排序的核心是“合并两个有序链表”，这对链表来说非常简单，只需要改变指针，不需要移动元素，也不需要额外的空间。

### 算法步骤

1.  **找中点 (Cut)**：使用 **快慢指针 (Fast-Slow Pointers)** 找到链表中点，将链表断开成两半。
    *   `slow` 走一步，`fast` 走两步。当 `fast` 到达末尾时，`slow` 就在中间。
2.  **递归 (Recursion)**：对左右两半分别进行递归排序。
3.  **合并 (Merge)**：将两个有序的子链表合并成一个有序链表。

### 代码细节

*   **Dummy Node (哨兵节点)**：在合并时，为了简化头节点处理，通常使用一个 dummy node。
    *   *注意*：在 Lemon Micro 的笔试中，因为禁止 `new` 节点，所以不能用 dummy node，必须手动处理 head。但在 LeetCode 中，为了代码清晰，我们通常使用它。

```cpp
ListNode dummy(0);
ListNode* tail = &dummy;
while (l1 && l2) {
    if (l1->val <= l2->val) { ... }
    else { ... }
}
return dummy.next;
```

## 复杂度分析

*   **时间复杂度**：`O(n log n)`。每一层递归都需要遍历 `n` 个节点，总共有 `log n` 层。
*   **空间复杂度**：`O(log n)`。这是递归栈的空间。如果是迭代写法（Bottom-up），可以做到严格的 `O(1)`。
