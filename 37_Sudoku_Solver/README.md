# 37. 解数独 (Sudoku Solver)

[LeetCode 链接](https://leetcode.cn/problems/sudoku-solver/)

## 题目描述

编写一个程序，通过填充空格来解决数独问题。
数独的解法需 遵循如下规则：
1.  数字 `1-9` 在每一行只能出现一次。
2.  数字 `1-9` 在每一列只能出现一次。
3.  数字 `1-9` 在每一个以粗实线分隔的 `3x3` 宫内只能出现一次。（请参考示例图）

## 思路解析

这道题是经典的**回溯算法 (Backtracking)** 应用。我们需要尝试在每个空格中填入 `1-9`，如果填入的数字满足规则，则继续填下一个空格；如果不满足，或者填到某一步发现无解，则回溯（撤销选择），尝试下一个数字。

### 1. 坐标转换：线性索引 `index`

你的代码中使用了一个整数 `index` 来表示当前处理到的格子位置。
数独是一个 `9x9` 的二维网格，总共有 `81` 个格子。
我们可以把二维坐标 `(i, j)` 映射到一维索引 `index` (范围 0 到 80)。

*   **映射公式**：`index = i * 9 + j`
*   **反向映射**：
    *   行号 `i = index / 9` (整数除法，向下取整)
    *   列号 `j = index % 9` (取模运算)

这样做的好处是，我们可以用一个单一的递归参数 `index` 来遍历所有格子，而不需要写两层循环或者处理行末换行的问题。当 `index == 81` 时，说明所有格子都处理完了。

### 2. 3x3 宫格的索引计算

代码中最难理解的部分可能是这一行：
```cpp
board[r / 3 * 3 + i / 3][c / 3 * 3 + i % 3]
```
这是在检查当前位置 `(r, c)` 所在的 **3x3 宫格** 是否已经包含数字 `num`。

#### 原理分解：

1.  **定位宫格的左上角坐标**：
    *   整个 9x9 面板被分成了 9 个 3x3 的宫格。
    *   `(r, c)` 所在的宫格，其左上角的行坐标是 `(r / 3) * 3`。
        *   例如：`r` 在 0,1,2 时，`r/3` 为 0，`*3` 后为 0。
        *   `r` 在 3,4,5 时，`r/3` 为 1，`*3` 后为 3。
    *   同理，左上角的列坐标是 `(c / 3) * 3`。
    *   记宫格起点为 `(startRow, startCol)`，其中 `startRow = r / 3 * 3`, `startCol = c / 3 * 3`。

2.  **遍历宫格内的 9 个格子**：
    *   我们需要检查宫格内的每一个格子。循环变量 `i` 从 0 到 8。
    *   我们要把 `0..8` 这 9 个数字映射到 3x3 的相对偏移量：
        *   相对行偏移：`i / 3` (结果为 0, 0, 0, 1, 1, 1, 2, 2, 2)
        *   相对列偏移：`i % 3` (结果为 0, 1, 2, 0, 1, 2, 0, 1, 2)

3.  **合并坐标**：
    *   当前检查的格子行坐标 = `宫格起点行` + `相对行偏移` = `r / 3 * 3 + i / 3`
    *   当前检查的格子列坐标 = `宫格起点列` + `相对列偏移` = `c / 3 * 3 + i % 3`

#### 举例：
假设我们要检查坐标 `(4, 7)`（第 5 行，第 8 列）。
*   `r=4`, `c=7`。
*   宫格起点：行 `4/3*3 = 3`，列 `7/3*3 = 6`。即宫格左上角在 `(3, 6)`。
*   当 `i=0` 时：检查 `(3+0, 6+0)` -> `(3, 6)`
*   当 `i=4` 时：检查 `(3+1, 6+1)` -> `(4, 7)` (自身，当然在填入前通常 board[r][c] 是空的，或者我们要跳过自身)
*   当 `i=8` 时：检查 `(3+2, 6+2)` -> `(5, 8)`

这样就完美遍历了 `(4, 7)` 所在的 3x3 宫格。

## 复杂度分析

*   **时间复杂度**：非常大，最坏情况下是指数级。但由于数独规则的强约束，实际回溯次数通常远小于最坏情况。
*   **空间复杂度**：O(1)（除了递归栈，board 本身是固定的 9x9）。
