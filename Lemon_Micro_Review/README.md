## 题目1：双向链表升序排序 (Strict In-place)

**难度评级**：Medium-Hard
*   **LeetCode 参考**：[148. Sort List](https://leetcode.cn/problems/sort-list/) (Medium)
*   **难点分析**：
    *   **绝对禁止造新节点**：你不能使用 `ListNode dummy(0)` 这种栈上对象，因为 `ListNode` 可能是纯虚基类，或者构造函数不可见。你只能操作现有的指针。
    *   **接口限制**：只能用 `get_next()`, `set_next()` 等接口，不能直接访问成员变量。
    *   **归并排序无 Dummy**：这比有 Dummy 节点难写得多，需要手动处理 `head` 的初始化。
    *   **双向链表**：需要额外维护 `prev` 指针，比单链表排序（LC 148）要繁琐得多。

**核心算法**：
*   归并排序 (Merge Sort)。
*   **技巧**：在 `merge` 函数中，手动选出第一个节点作为 `head` 和 `tail`，然后开始循环。

**复习建议**：参考 `Lemon_Micro_Review/dll_sort_strict.cpp`。重点看 `merge` 函数中如何在**没有 dummy 节点**的情况下合并链表。

## 题目3：矩阵死循环检测

**难度评级**：Medium-Hard
*   **LeetCode 参考**：[1059. All Paths from Source Lead to Destination](https://leetcode.cn/problems/all-paths-from-source-lead-to-destination/) (Medium) 或 [207. Course Schedule](https://leetcode.cn/problems/course-schedule/) (Medium) 的变种。
*   **难点分析**：
    *   **超时 (TLE)**：这是最大的坑。如果不加记忆化（三色标记），复杂度指数级上升。
    *   **栈溢出**：深度过大的 DFS 可能会爆栈。
    *   **状态定义**：需要区分“正在访问”（环）和“已访问”（安全）。

**复习建议**：参考 `Lemon_Micro_Review/matrix_cycle.cpp`，学习如何使用 `status` 数组进行剪枝和环检测。

## 总结与进面分析

**总体难度**：这张卷子的难度在 **Medium 到 Hard** 之间，主要难在**工程限制**（不能造节点、OOP 接口）和**边界条件**。

### 为什么柠檬微趣出这么难？（行业背景）

你可能会觉得：“这不就是故意刁难人吗？” 其实不然。柠檬微趣是一家做**消除/合成类手游**（Merge Games）的公司。

1.  **内存敏感**：在手机上运行游戏，内存极其宝贵。**“不准造新节点”**、**“In-place 操作”** 是游戏引擎开发的日常要求。如果每帧都 `new` 几个节点，GC（垃圾回收）或者内存碎片会卡死游戏。
2.  **OOP 架构**：游戏开发大量使用**继承和虚函数**（如 Unity/Unreal 的 Component 系统）。题目 1 和 4 考察的就是你能否在既定的 OOP 框架下写出高性能代码。
3.  **鲁棒性**：题目 2（IPv4）考察的是处理脏数据的能力，这在解析服务器协议或配置文件时非常关键。

**这说明**：他们不是在招“刷题机器”，而是在招“**有工程思维的 C++ 开发者**”。
