# 滴滴笔试题：精密零件加工 (Precision Parts Processing)

## 题目描述

小Q需要加工两个精密零件，这两个零件分别有 $n$ 个关键位置，编号 $1$ 到 $n$。
初始时，第一个零件的第 $i$ 个位置高度为 $a_i$，第二个零件为 $b_i$。
现在需要对零件进行精细加工（只能磨掉，不能增加），得到新的高度 $a'_i$ 和 $b'_i$。

要求满足以下条件：
1.  **磨掉操作**：$0 \le a'_i \le a_i, \quad 0 \le b'_i \le b_i$。
2.  **拼接高度一致**：存在某个定值 $h$，使得对于所有 $i$，都有 $a'_i + b'_i = h$。
3.  **相邻平滑约束**：对于所有 $i < n$，满足 $|a'_{i+1} - a'_i| \le k$。
    *   注：由于 $a'_i + b'_i = h$，所以 $|b'_{i+1} - b'_i| = |(h - a'_{i+1}) - (h - a'_i)| = |a'_i - a'_{i+1}|$，因此该条件同时也保证了零件 B 的平滑性。

**目标**：求最少需要磨掉多少高度的零件？即最小化 $\sum (a_i - a'_i) + (b_i - b'_i)$。

## 题目分析

### 1. 转换目标
求最小磨掉的高度，等价于求**最大保留的高度**。
总初始高度 $Total = \sum (a_i + b_i)$ 是固定的。
保留的总高度 $= \sum (a'_i + b'_i) = \sum h = n \times h$。
因此，我们的目标就是**最大化 $h$**。

### 2. 为什么是二分答案？
*   **单调性**：如果高度 $h$ 是可行的（即存在满足所有约束的序列 $a'_i$），那么任何小于 $h$ 的高度通常也是可行的（我们可以进一步磨掉零件来达到更小的高度，只要保持差分约束即可）。
*   **可行性检查**：给定一个 $h$，验证是否存在序列 $a'_i$ 满足：
    *   $L_i \le a'_i \le R_i$
    *   $|a'_{i+1} - a'_i| \le k$
    *   其中 $L_i, R_i$ 由 $a'_i \in [0, a_i]$ 和 $b'_i = h - a'_i \in [0, b_i]$ 推导而来。

### 3. 如何验证 $h$ 是否可行？（Greedy Range Intersection）
对于给定的 $h$，每个位置 $i$ 的 $a'_i$ 必须满足：
1.  $a'_i \le a_i$
2.  $a'_i = h - b'_i \ge h - b_i$
3.  $a'_i \ge 0$
4.  $a'_i \le h$ (因为 $b'_i \ge 0$)

综合起来，对于每个 $i$，$a'_i$ 的取值范围是：
$$ [\max(0, h - b_i), \min(a_i, h)] $$
记为 $[Low_i, High_i]$。如果 $Low_i > High_i$，则 $h$ 不可行。

接下来，我们需要找到一个序列 $x_0, x_1, \dots, x_{n-1}$，使得 $x_i \in [Low_i, High_i]$ 且 $|x_{i+1} - x_i| \le k$。
这可以通过**前向递推**来解决：
*   设 $i-1$ 位置的可行区间为 $[CurL, CurR]$。
*   那么 $i$ 位置从 $i-1$ 转移过来的可行范围是 $[CurL - k, CurR + k]$。
*   $i$ 位置自身的可行范围是 $[Low_i, High_i]$。
*   $i$ 位置的最终可行范围就是两者的**交集**：
    $$ [\max(Low_i, CurL - k), \min(High_i, CurR + k)] $$
*   如果交集为空，说明无法延续，返回 `false`。
*   如果遍历完所有位置交集都不为空，返回 `true`。

### 4. 为什么你的代码只过了 45%？
原来的代码逻辑其实大部分是正确的，但可能存在以下问题导致无法 AC：
1.  **I/O 性能**：$T=10^5, N=10^5$，如果用普通的 `cin/cout` 可能会 TLE。加上 `ios::sync_with_stdio(false)` 是必须的。
2.  **数据类型**：虽然 $h$ 在 `int` 范围内，但在计算区间交集时，涉及加减法最好使用 `long long` 避免溢出风险（尽管这题 $2 \cdot 10^9$ 刚好在 `int` 边缘）。
3.  **check 函数逻辑**：你的 `check` 函数本身逻辑是对的，可能是边界条件（如 `h - b[i]` 为负数时的处理）或者类型转换上的细微差异。我在新代码中使用了 `max(0LL, ...)` 显式确保类型安全。

### 复杂度分析
*   二分查找范围：$[0, 2 \cdot 10^9]$，次数约为 31 次。
*   每次 Check：$O(N)$。
*   总复杂度：$O(T \cdot N)$ 是不行的。**但是**，题目保证 $\sum n \le 2 \cdot 10^5$。
*   所以总复杂度是 $O(\sum n \cdot \log(\text{MaxH})) \approx 2 \cdot 10^5 \times 31 \approx 6 \times 10^6$。完全可以在 1 秒内跑完。
